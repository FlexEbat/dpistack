# Docker или нативно: что где может работать

Каждая часть, у которой есть образ, может работать контейнером или нативно, в любых сочетаниях. Контейнеры используют сеть хоста, поэтому нативная часть и контейнер находят друг друга по одним и тем же адресам хоста; при смешивании вручную ничего настраивать не нужно. Команда `sudo dpistack runtime` показывает таблицу ниже для вашей установки: рантайм каждой части и проверку каждой связи.

| Часть | Docker | Примечание |
|---|---|---|
| Suricata | да | в контейнере нет плагина nDPI и режима IPS; для них нужна нативная Suricata |
| Плагин nDPI | нет | собирается в нативную Suricata |
| Обновление правил | как Suricata | выполняется на хосте или внутри контейнера Suricata |
| EveBox | да | |
| ntopng | да | |
| Redis | как ntopng | всегда в том же рантайме, что и ntopng |
| VictoriaMetrics / Prometheus | да | только выбранный бэкенд |
| node_exporter, Grafana | да | |
| Панель | да | привилегированный контейнер с пространством процессов хоста; до `dpistack` достаёт через `nsenter` |
| Сторож | нет | systemd-таймер хоста |
| nginx | нет | пакет хоста, только при `ACCESS_MODE=nginx` |
| Правила файрвола | нет | правила ядра хоста; они защищают и контейнеры в сети хоста |
| Установщик и `dpistack` | нет | скрипты хоста |

## Как части находят друг друга

- Suricata пишет `eve.json` в `/var/log/suricata`; EveBox и панель читают тот же путь хоста, контейнер Suricata или нет.
- ntopng использует Redis на `127.0.0.1:6379`.
- Бэкенд метрик снимает метрики с панели и node_exporter по адресу доступа (с nginx порт панели плюс 10000); Grafana читает бэкенд по его порту.

`dpistack runtime --json` отдаёт те же данные для скриптов: список частей, флаг `mixed` и список связей, где `ok` равно `true`, `false` или `null` (один из концов связи не запущен).

## Отклоняемые сочетания

nDPI с контейнером Suricata и IPS с контейнером Suricata отклоняются с указанием причины проверкой конфигурации, preflight и командой `dpistack mode ips`. Всё остальное можно смешивать.
