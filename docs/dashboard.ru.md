# Панель управления

[English](dashboard.md) | Русский

Веб-панель показывает состояние стека и позволяет им управлять без командной строки. Адрес по умолчанию: `http://127.0.0.1:9800` (см. «Доступ» в [deployment.md](deployment.ru.md)). Вход по паролю обязателен; пароль хранится как хэш argon2id, сменить его можно командой `dpistack panel-passwd` или в меню управления.

Интерфейс адаптивный: на широком экране навигация слева, на узком это плавающая панель с меню, которое открывается на весь экран. Тема светлая или тёмная по настройке системы. Страница не загружает внешних шрифтов, скриптов и картинок (шрифты Geist и иконки Phosphor отдаёт сама панель) и работает в сети без выхода в интернет.

## Редакции

`PANEL_EDITION` выбирает, какая панель отдаётся. У обеих редакций одни и те же экраны, API и функции; различаются только внешний вид и работа в браузере. Меню установщика спрашивает, какую вы хотите, позже её можно сменить на экране «Настройки».

| Редакция | Вид | Когда выбирать |
| --- | --- | --- |
| `full` (по умолчанию) | тёмная консоль: плоские поверхности, один холодный синий акцент, шрифт Geist, боковая панель, блоки, которые один раз плавно появляются при прокрутке, и тихий фон из частиц (останавливается на скрытой вкладке и учитывает `prefers-reduced-motion`) | рабочее место или любой хост, где у браузера есть запас |
| `lite` | простая светлая страница: системные шрифты, без фонового холста и анимаций, маленький файл стилей | небольшой хост, старый браузер или медленная связь |

Сервер отдаёт стили и фоновый скрипт выбранной редакции, поэтому страница lite никогда не загружает полную.

## Экраны

| Экран | Что на нём |
| --- | --- |
| Обзор | общий статус стека, состояние компонентов, ключевые показатели |
| Компоненты | запуск, остановка и перезапуск каждого компонента, режим IDS/IPS с подтверждением и обратным отсчётом, интерфейсы захвата |
| Настройки | все параметры `dpistack.conf` и секреты |
| Конфиги | редактор файлов `suricata.yaml`, `evebox.yaml`, `ntopng.conf`, `local.rules`, `enable.conf`, `disable.conf`, `modify.conf`, `drop.conf`; проверка, сохранение с резервной копией и откат |
| Правила | источники правил, группы, отдельные правила по sid, поиск, обновление с откатом при ошибке |
| Логи | журналы компонентов с потоковым просмотром |
| События | события из `eve.json` с фильтрами и выгрузкой |
| Метрики | графики по статистике Suricata и состоянию хоста |
| Тесты | проверочные тесты (BitTorrent, HTTPS) |
| Оповещения | сообщения watchdog и каналы доставки |

## Экран «Настройки»

Экран строится из схемы параметров, которую отдаёт сама программа, поэтому показывает ровно те ключи, которые знает установленная версия: те, что раньше были разделены между установщиком и командой управления, теперь в одном месте.

- Параметры сгруппированы: захват трафика, компоненты и установка, события и хранение, правила, доступ и порты, метрики, контроль и оповещения, проверочные тесты. Под каждым параметром короткое описание. Основные параметры видны сразу, остальные появляются по переключателю «Расширенные настройки».
- Поле подходит типу параметра: список для перечислений, число с границами для целых, текст для остальных. Очевидные ошибки видны сразу, окончательная проверка за сервером.
- **Проверить** ничего не записывает: показывает ошибки по ключам, вес изменения и занятые порты. **Применить** проверяет, записывает и применяет; **Сбросить** возвращает введённые значения.
- Метка «переустановка» у параметра значит, что изменение запускает установку или пересборку компонента. Перед этим панель просит подтверждение, а ход применения показывается в журнале на этом же экране.
- Занятый порт панель показывает вместе с именем процесса и кнопкой «Взять N» для ближайшего свободного.
- Расширение доступа (`ACCESS_MODE` не `localhost`) требует отдельного подтверждения.
- Секреты (`ALERT_TG_TOKEN`, `ALERT_SMTP_URL`, `METRICS_TOKEN`) никогда не показываются: видно только «задан» или «не задан». Новое значение вводится в отдельное поле, пустое удаляет секрет.

Те же действия доступны из командной строки: `dpistack settings list|check|set|secret|job` (см. [operations.md](operations.ru.md)).

## Пользователи и роли

В панели может быть несколько пользователей. Первый — `admin`, с паролем, заданным при установке (`sudo dpistack panel-passwd`). Входите по имени и паролю; пустое имя означает `admin`.

| Роль | Что может |
|---|---|
| viewer | смотреть все экраны, кроме Configs |
| analyst | viewer, запускать самопроверки, читать аудит |
| operator | analyst, управлять компонентами, править правила |
| admin | всё, включая настройки, конфиги, режим IPS, обновления и пользователей |
| custom | ровно те права, которые вы отметите |

Экран Account меняет ваш пароль, а у тех, кто может управлять пользователями, ещё и добавляет пользователей, меняет роли, отключает и удаляет. То же из командной строки (пароль читается из stdin):

```
printf '%s\n' 'длинный пароль' | sudo dpistack users add anna operator
sudo dpistack users list
sudo dpistack users role anna custom --perms view,rules.edit
sudo dpistack users disable anna
```

Последнего пользователя, который может управлять пользователями, нельзя удалить, отключить или понизить. Смена роли или пароля завершает сессии этого пользователя; отключённый пользователь теряет доступ сразу.

## Безопасность панели

- Панель работает не от root; привилегированные действия выполняет вызовом `sudo -n dpistack <команда>`, где `dpistack` пускает пользователя панели только к командам управления и сверяет аргументы со списками.
- Редактор конфигов равен root-доступу к хосту: правки `suricata.yaml` позволяют выполнить чужой код. Не открывайте панель в сеть без необходимости; режимы `lan` и `nginx` требуют подтверждения, для `lan` HTTP без TLS виден в сети, используйте `nginx` с TLS или SSH-туннель.
- Каждый изменяющий запрос защищён токеном CSRF; сессия по cookie.
