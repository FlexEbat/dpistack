# Установка, обновление, удаление

## Требования

- Linux с systemd, root-доступ, архитектура `amd64` или `arm64`.
- Доступ в интернет на время установки (пакеты, репозитории, релизы компонентов).
- Для компонентов в Docker: Docker с плагином `compose`.
- Список платформ и что на каждой устанавливается: [platforms.md](platforms.md).

Команда `dpistack` и `install.sh` запускаются только от root. Без root они завершаются с кодом 1 и сообщением `команда запускается только от root`.

## Способы получить установщик

Из клона репозитория:

```
git clone https://github.com/FlexEbat/dpistack.git
cd dpistack
sudo ./install.sh install
```

Одним файлом: `dpistack-install.sh` в корне репозитория. Он собирается `scripts/bundle.sh` из тех же `install.sh`, `lib/`, `templates/` и `bin/` и принимает те же команды: `sudo bash dpistack-install.sh install`. Панель в файл не входит: рядом должен лежать готовый бинарник `dpistack-panel-linux-amd64` (или `-arm64`) из архива релиза либо каталог `panel/` с Go нужной версии. Из канала (`curl ... | bash`) файл запустится, но меню не получит ввода, поэтому сначала скачайте его.

## Меню и без вопросов

На терминале `install` открывает текстовое меню. «Быстрая установка» спрашивает интерфейсы, способ установки Suricata, режим доступа и пароль панели; остальные разделы (захват, компоненты, EVE, правила, доступ, метрики, сторож, тесты) открываются по желанию, а `--advanced` спрашивает все ключи. Установка стартует отдельным пунктом меню.

Без терминала или с `-y` вопросов нет, недостающее берётся из умолчаний:

```
sudo ./install.sh install -y --set IFACES=eth0 --set ACCESS_MODE=localhost
```

План без изменений в системе:

```
sudo ./install.sh install --dry-run -y
```

Итоговый отчёт один раз показывает сгенерированный пароль панели (на диске остаётся только хэш argon2id) и, если включён экспорт метрик, токен `/metrics`. Пароль можно задать заранее: `DPISTACK_PANEL_PASSWORD=... sudo -E ./install.sh install -y`.

## Занятые порты

Перед установкой проверяются порты панели (`PANEL_PORT`, 9800), EveBox (`EVEBOX_PORT`, 5636), ntopng (`NTOPNG_PORT`, 3000) и хранилища метрик. С nginx проверяется и порт за ним (публичный порт + 10000).

- В меню занятый порт показывается как предупреждение: называется процесс, который его держит, и предлагается ближайший свободный порт. Enter принимает его, можно ввести свой, `q` оставляет порт как есть (тогда проверка перед установкой остановится на нём).
- Без терминала установка останавливается с кодом 3, а в сообщении указан свободный порт: `порт 9800 (PANEL_PORT) уже занят (держит: nginx); свободный: --set PANEL_PORT=9801`.
- Из панели и командой `dpistack settings set` смена порта на занятый отклоняется с тем же сообщением, файл конфигурации не меняется.

## После установки

Доступна команда `dpistack` (копия установщика в `/usr/local/sbin`). Без аргументов она открывает меню управления: настройка, статус, логи, тесты, обновление, удаление, пароль панели. По умолчанию панель слушает `http://127.0.0.1:9800`, EveBox `5636`, ntopng `3000`. С другой машины: `ssh -L 9800:127.0.0.1:9800 user@host`.

`dpistack-ctl` остаётся символической ссылкой на `dpistack`, чтобы работали службы, созданные прежними версиями; в новых сценариях пользуйтесь `dpistack`.

## Изменение настроек

```
sudo dpistack reconfigure                 # меню или применение dpistack.conf
sudo dpistack reconfigure --dry-run -y    # какие ключи изменились и какие шаги затронуты
sudo dpistack settings set --apply STATS_INTERVAL_SEC=45
```

Лёгкое изменение применяется сразу. Тяжёлое (смена источника Suricata, runtime компонента и подобное) требует `--force` или `settings set --apply-heavy`: установщик перезаписывает файлы, правленные вручную, и сохраняет их копии. Справочник параметров: [configuration.md](configuration.md).

## Обновление

```
sudo dpistack upgrade
```

Обновляются пакеты и закреплённые версии компонентов, копия установщика и панель. Версии компонентов можно закрепить ключами `*_VERSION` и `PIN_VERSIONS=yes`.

## Удаление

```
sudo dpistack uninstall            # службы, таймеры, правила firewall dpistack, копии программы
sudo dpistack uninstall --purge    # и конфиги, данные компонентов, пользователи
```

Пакеты системы не удаляются. Цепочка `DPISTACK` и правила, добавленные dpistack, убираются; чужие правила не затрагиваются.
